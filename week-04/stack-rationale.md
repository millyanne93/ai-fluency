## Stack Rationale

I chose **plain HTML/CSS with AI assistance**, hosted on **Netlify**.

### Alternatives considered

- **No-code (Framer):** I considered this for its speed, but I wanted full control over my site's code and preferred to avoid platform lock-in.

- **Framework (Next.js):** I considered Next.js because it offers powerful features, but it would add unnecessary complexity for a portfolio that doesn't require dynamic functionality.

### Why I chose this stack

This option is free, simple to build, and easy to maintain. My portfolio only needs to present my projects, case studies, screenshots, architecture diagrams, GitHub repositories, and contact information, so a static site meets all of my current requirements.

### Can I maintain this?

Yes. I built the site myself with AI assistance, so I understand how it works and can confidently update it as I complete new projects.

### Does it show my work well?

Yes. A static portfolio clearly showcases my backend and cloud engineering work through project screenshots, technical explanations, architecture diagrams, and links to live demos and source code.

### Backend

A backend is not necessary at this stage because the portfolio is intended to showcase my work rather than provide dynamic functionality.
